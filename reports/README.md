# 토큰증권 제도 시행에 대비한 교보증권의 사업전략

[us-tokenization-kyobo.html](us-tokenization-kyobo.html)을 다운로드해 브라우저에서 연다. 데이터·코드·스타일을 포함한 단일 파일이다. 보고서 열람에는 별도 설치나 네트워크가 필요하지 않으며, 원문 출처를 방문할 때는 인터넷이 필요하다. GitHub 파일 화면은 웹페이지 호스팅 화면이 아니다.

기준일: **2026-10-04**. 공개자료를 바탕으로 교보증권이 유지할 수익, 초기에 검토할 금융 업무, 투자 확대 조건을 분석한다. 회사의 확정 사업계획이나 내부 고객·원가 자료를 제시하는 문서는 아니다.

## 목적과 형식

경영전략·디지털사업·지원부문의 사업 검토를 위한 보고서로 구성했다. 기술 동향을 나열하거나 투자자의 주식 매매 판단을 제시하기보다, 제도 시행 후 어떤 고객·업무에 진입하고 어느 조건에서 투자를 확대할지 검토한다.

기본 형식은 자본시장연구원 [이슈보고서 24-04](https://www.kcmi.re.kr/report/report_view?report_no=1777)의 **현황 → 전략 변화 → 대응과제 → 시사점** 전개를 참고했다. 사업 후보는 [McKinsey 토큰화 보고서](https://www.mckinsey.com/industries/financial-services/our-insights/from-ripples-to-waves-the-transformational-power-of-tokenizing-assets)의 효익·실행 가능성·도입 조건을 참고해 비교했다. 해외 시장규모 전망을 교보의 예상 매출로 사용하지 않았다. 블랙록 등 미국 금융기관 자료는 사업모델과 상품 권리를 확인하는 근거로 사용했다.

사실의 출처, 회사 발표의 상태, 전망의 조건은 문장과 주석으로 표현한다. 본문에 영문 분류 배지를 붙이지 않는다. 근거의 성격과 검토 한계는 데이터와 개별 사례에 남겼다.

## 구성

1. **교보증권의 사업여건과 제도 변화:** 수익·자금의 흐름, 경쟁·제휴 관계, 국내 초기 적용 범위.
2. **미국 금융기관의 사업모델과 수익조건:** 운용·판매, 증권서비스, 사모자산 접근의 세 방식과 보수·위험의 귀속.
3. **교보증권의 진입대안과 우선순위:** 기관 사모사채 주선·사후관리를 첫 검토 후보로 두고 MMF 계약 가능성과 비교. 기존 수익 대체분과 추가 운영·자금 비용을 차감한 손익 평가.
4. **단계별 추진방향과 운영과제:** 제도·수요별 투자 범위, 지원 업무·AI 활용, 착수·확대·중단 기준.

부록에는 공시 부문별 손익, 미국 12개 사례의 상세 권리·운영 조건·출처, 설명용 증분 손익 계산을 수록했다. 계산 도구의 입력은 실제 상품 가격이나 회사 전망이 아니다.

## 근거와 소스

[reviewed_snapshot.json](source/reviewed_snapshot.json)에 공시 전사값·사례·출처 URL·자료 기준일·분석 범위와 작성 목적을 담았다. 원문은 교보 DART, 한국 금융위원회, 미국 발행자·인프라 공식 문서와 SEC 공시를 중심으로 사용했다. 교보 AI 구축은 공급사 발표 보도로 구분했다. 일부 JPM TCN 자료는 직접 접근 제한으로 공식 검색색인을 검토한 범위를 표시했다.

[ReportContent.jsx](source/ReportContent.jsx)와 [report.css](source/report.css)는 보고서의 작성 영역이다. canonical Data report runtime의 `src/content/report/`에 대응하며, snapshot은 `src/data.json`에 대응한다. 보호된 공통 UI·차트·출처·편집·내보내기 기능을 유지해 컴파일하고, split build에서 offline HTML로 내보냈다. 이 소스 묶음 자체가 독립 npm 프로젝트는 아니다.

## 검증 범위

[verification.json](verification.json)에 검증 및 미실시 항목을 기록했다. 빌드·오프라인 내보내기, 데이터 구조·단위·합계, 표와 계산 산식을 확인했다. 저장소의 합성데이터 실행과 22개 테스트도 통과했다. 이 테스트는 미국 사례의 법률 효과나 교보의 실제 수익성을 검증하지 않는다.

현재 실행 환경에는 사용할 수 있는 브라우저 바이너리가 없어 실제 화면·클릭·모바일 동작 검증을 실시하지 못했다. 빌드 성공을 화면 검증의 통과로 표시하지 않았다.

## 디지털 금융환경과 AI 에이전트 시대의 증권업 통합 보고서

**[디지털 자산과 AI 에이전트가 바꾸는 증권업의 수익구조](digital-finance-agentic-securities.html)** · 기록일·자료 기준일 **2026-10-05**, 통합 개정 **2.0**.

기존 증권업·교보증권 분석에 [금융환경과 기관 대응 보고서](financial-environment-response.html)의 경제 원리, 자산 권리, 세계 규제, 미국·한국 기관, 거시 자금 전파, AI 위임·지급·수탁·반환, 실행·관측 기준과 근거 부록을 해당 장에 통합했다. 기존 제목·목차 경로·주석과 출처를 보존하며 같은 사실의 반복 설명은 줄인다. 환경 보고서는 통합에 사용한 별도 자료로 유지한다.

[브라우저 미리보기](https://htmlpreview.github.io/?https://raw.githubusercontent.com/Eom-TaeJun/sto-ai-frontier/main/reports/digital-finance-agentic-securities.html). 다운로드한 HTML에서도 본문·검색·자산 및 시나리오 비교·기관 필터·근거 펼치기·인쇄가 작동한다.

[통합 생성 스크립트](../scripts/merge_financial_reports.py)는 기존 보고서 스냅샷과 환경 보고서로 동일 HTML을 재생성한다. 저장소 루트에서 `python scripts/merge_financial_reports.py`를 실행한다. 이전 스냅샷이 없는 얕은 복제에서는 스크립트에 명시된 기준 커밋을 먼저 가져오거나 `--base`로 해당 원본 HTML을 전달한다. 원본·보고서 생성·통합 작업은 새 법률 조사나 기관 수익성 검증을 뜻하지 않는다.

[통합 검증 기록](digital-finance-agentic-securities.verification.json)은 원본 보존·중복 ID·내부 연결·화면과 기능·기존 프로토타입 검사의 범위를 구분한다. 자료 기준일을 실제 검사 시각으로 바꾸지 않는다.
