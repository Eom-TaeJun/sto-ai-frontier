# 어떤 결과를 보면 판단을 바꿀 것인가

**우선 확인할 것은 법적·운영 조건, 고객의 반복 이용, 기존 방식 대비 순편익이다.** 현재 실제 고객·비용 자료가 없어 아래는 측정 설계이며 달성 실적이 아니다. 수치 임계값은 자료를 확보한 뒤 기존 방식과 위험 허용 수준에 맞춰 정한다.

| 가설 | 관측할 Signal | 비교 기준·분모 | 강화 | 약화·기각·대응 |
|---|---|---|---|---|
| 초기 기관 업무를 표준화할 수 있음 | 재거래, 서식 재사용, 정정·대조시간 | 같은 유형의 전체 거래, 기존 방식 | 반복 계약과 총원가 감소 | 일회성 구축·이중 대조 증가 → 범위 축소 |
| 차별화 자산이 추가 수익을 만듦 | 발행 후 수익배분, 재투자, 수수료와 총비용 | 판매·평가·보관·민원 포함 상품별 손익 | 반복 수요와 순수익 | 거래·매각 부진, 분쟁 증가 → 보류·종료 |
| 제휴가 자체 구축보다 유리함 | 연계 비용, SLA, 복구·정정 책임, 재사용 | 자체 구축과 기존 처리의 총비용 | 여러 거래 재사용·비용 절감 | 최소료·종속·예외 비용 상승 → 계약 재검토 |
| 온체인 결제가 효율적임 | 실패·복구 시간, 대기 자금, 상환 지연 | 같은 거래의 기존 결제·네팅 효과 | 위험 감소와 자금·운영비 순편익 | 선자금·실패 손실 증가 → 확대 중단 |
| AI가 전체 업무를 줄임 | 초안·검토·수정·예외 처리시간, 오탐·누락 | 동일 문서·난도·건수, 사람 기준선 | 전체 시간 감소, 중대한 누락 통제 | 검토 증가 또는 오류 → 규칙 기준선·사람 처리로 복귀 |

## 프로젝트 입력 규칙

코드는 금융 승인 대신 확인 요청을 만든다. 자산 클래스별 권리·운영 조건을 확인하고, 채무성 자산에 한해 같은 기간의 가용 현금흐름/원리금 지급액을 계산한다.

- 1.2배 검토선·20% 감소·자료 90일은 임의 POC 가정이다.
- 권리·중복 담보 등이 실패한 경우 수치가 좋아도 HOLD다.
- 미확인 자료는 NEEDS_REVIEW다. 빠진 값은 null로 남긴다.
- READY_FOR_INTERNAL_REVIEW도 발행 승인·투자 적합성·수익 보장이 아니다.
- 문서 검사는 원문 구간과 근거 ID를 함께 남긴다. 미탐이 없다는 보장은 하지 않는다.

## 판단 변경 기록에 남길 것

`이전 가설 → 새 자료의 출처·시점 → 달라진 조건 → 강화/약화/기각/supersede → 다음 행동과 담당자`

예: 기관 거래의 반복 수요가 확인되지 않으면 ‘기관 우선’ 가설을 유지할 이유가 약해진다. 반대로 콘텐츠 정산 자료·권리가 표준화되고 순수익이 확인되면 해당 업무가 먼저 유효할 수 있다. 어느 자산을 먼저 해야 할지는 토큰 발행의 기술적 쉬움만으로 결정하지 않는다.
