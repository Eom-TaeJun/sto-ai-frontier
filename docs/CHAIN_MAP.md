# 업무와 책임의 재배분

**토큰증권은 증권의 내용과 원장 형태를 구분해야 한다.** 권리 표시와 정보 처리가 바뀌어도 자산·돈·책임이 자동으로 사라지는 것은 아니다. 정책 근거는 [EVIDENCE_MAP](EVIDENCE_MAP.md)의 F1~F3을 참고한다.

| 객체 | 경제적·법적 관계 | 바뀔 수 있는 것 | 계속 확인할 것 |
|---|---|---|---|
| 발행인·원소유자 | 자산 또는 사업의 권리를 증권 구조에 연결 | 발행 자료와 권리 기록의 표준화 | 실제 소유·양도·담보·도산 시 권리 |
| 채무자·수익 지급자 | 채권 변제 또는 이용료·매출 지급 | 지급 자료의 자동 대조 | 불이행·공제·분쟁·집중 위험 |
| 신탁업자·관리자 | 신탁 재산·권리·배분 관리 | 기록과 배분 지시의 연결 | 자산 격리·처분·세금·관리 책임 |
| 투자자 | 증권을 보유하고 손익·권리를 부담 | 접근·보유기록·권리행사 방식 | 적합성·유동성·환매 조건 |
| 교보증권 | 인가 범위 안에서 주선·판매·계좌관리 등 | 반복 업무 자동화, 외부 자산·기술 연결 | 공시·설명·판매·관리 책임과 이해상충 |
| 예탁결제원·원장 참여자 | 전자등록 체계와 권리 기록 관리 | 분산원장 정보 공동 기재·연계 | 원장 정합성·정정·장애 복구 |
| 수탁·기술 업체 | 계약에 정한 자산·키 통제 또는 시스템 제공 | 데이터 연계·보안·복구 작업 | 기술적 키 통제와 법적 수탁 관계의 일치 |
| 은행·결제 인프라 | 매매 대금 지급과 결제 지원 | 장래 온체인 DvP 연계 가능성 | 현금 준비·최종성·상환·운영 시간 |
| 해외 유통 파트너 | 현지 인가·투자자·배포 계약에 따른 유통 | 해외 자산·투자자 경로 확대 가능성 | 국가별 판매·공시·외환·수탁 요건 |

## 이동을 추적하면 남는 질문

| 이동 | 예상 변화, INTERPRETATION | 교보의 선택·검증 |
|---|---|---|
| Money | 투자자 대금이 자산/발행인으로, 수익이 보유자에게 배분 | 고객의 지불 의사, 반복 거래, 배분 대조 비용 확인 |
| Asset | 증권 기록이 분산원장 형태를 취할 수 있음 | 기초자산 권리와 증권 권리의 연결을 따로 검토 |
| Risk | 발행·대조 오류 일부 감소 가능, 연결·키·장애 위험 추가 | 대사·정정·복구 기준과 계약별 손실 부담 설정 |
| Information | 자료 추출·비교가 자동화되고 여러 참여자가 공유 | 출처·시점·권한·불일치 표시, 자료 최소화 |
| Decision Right | 자동화가 후보·예외를 만들지만 승인은 별도 | 상품·법무·준법·운영·고객의 권한 구분 |

## AI 도입에서 업무를 어떻게 나눌 것인가

| 단계 | 도구가 맡는 후보 업무 | 사람이 맡는 일 | 현재 구현 |
|---|---|---|---|
| 정보 찾기 | 문서 추출과 출처 연결 | 사용 권한·원문·시점 확인 | 구조화 합성 입력 읽기 |
| 판단 보조 | 수치 대조, 누락·예외 표시 | 경제적 의미·권리·상품성 판단 | 규칙·계산 기준선 |
| 실행 | 승인된 범위의 초안·작업 요청 | 실행 범위 설정·승인 | 로컬 검토 결과 파일 생성 |
| 예외 승인 | 예외 이유와 근거 제시 | 권한을 가진 담당자가 승인 | 예외·소유자 기록, 승인 기능 없음 |

LLM을 추가한다면 원문·인용 구간·추출값을 함께 제출하도록 하고, 수치 계산은 별도 규칙 엔진에서 검증한다. 고객 주문·거래·공시 제출을 연결하려면 독립 승인·권한·기록·실패 복구를 먼저 설계한다. 이 설계 자체를 실제 도입 성과로 주장하지 않는다.
