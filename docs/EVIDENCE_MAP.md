## 이 저장소가 추가한 판단

| 구분 | 내용 | 근거·검증 |
|---|---|---|
| THEORY | 토큰화가 채무자의 지급능력·기초자산 가치·고객의 매수 의사를 직접 만들어 주지는 않음 | 권리와 위험의 발생 원인 구분 |
| INTERPRETATION | 증권사의 역할이 일괄 소멸하기보다 정보·발행·권리관리 업무의 경계가 바뀔 수 있음 | 업무와 책임 지도 |
| HYPOTHESIS | 반복되는 기관 거래 업무를 좁게 표준화하면 초기 통합·사후관리 비용을 줄일 수 있음 | 기존 방식 대비 고객·원가 검증 필요 |
| HYPOTHESIS | 교보의 자산·기술 제휴를 활용한 선별형 서비스가 자체 생태계 일괄 구축보다 유리할 수 있음 | 제휴 가격·비독점성·수요·운영 책임 확인 필요 |
| UNKNOWN | 교보의 해당 사업 실제 고객 수·예산·기술 연결·수익·인가 범위·평판 손실 비용 | 공개 자료만으로 확정하지 않음 |

2026 반기 기준선으로 기존 ‘기관 MMF·사채 우선’ 가설을 수정했다. 주식·해외선물 중개와 조달·운용 마진의 방어를 먼저 검토하고, 신규사업 안에서는 반복 사모사채·기관 MMF의 실제 고객 수요와 추가 손익을 비교한다. 허용 자산 목록 자체는 상품 우선순위의 증거가 아니다.

## 교차점검

Source Check: MOU·교육 발표를 출시·성과로 바꾸지 않는다.

Mechanism Check: 기록 자동화 → 대조·처리시간 변화 → 고객 이용·가격 → 손익의 전달경로를 확인한다. 이 연결 중 빠진 부분은 가설이다.

Reality Check: 재거래, 수작업 시간, 오류·정정·민원, 추가 수익과 총비용을 실제 자료로 확인해야 한다.

Counterfactual / Update Check: 기존 전자증권과 통상적인 자동화만으로 같은 개선이 되는지 비교하고, 토큰화 추가 비용이 편익을 넘으면 도입 가설을 기각한다.
