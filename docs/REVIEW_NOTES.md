# 원본 초안에서 바꾼 판단

출발 자료: Meta AI 공유 대화와 `kyobo-sto-ai-frontier-v2.zip`, 검토일 2026-10-04. 파일 구조와 문제의식은 참고하되 실제 코드·근거와 일치하도록 수정했다.

| 원본의 주장·구현 | 수정 | 이유 |
|---|---|---|
| 점수 70 이상이면 즉시 토큰화 가능 | 권리·운영 게이트와 클래스별 검토, 발행 승인 없음 | 점수는 권리·규제·판매·연계를 증명하지 못함 |
| 공기업에 높은 점수, MMF까지 DSCR 적용 | 실존 기업명 제거, 채무성 자산에만 현금흐름 계산 | 합성 수치가 실제 재무·상품처럼 읽힐 수 있음 |
| LLM RAG, MPC mock, AI 공시 에이전트 구현 | 규칙 기반 문서 대조 POC로 정확하게 표시 | 원본 실제 구현은 정규식이며 해당 기술 연결 없음 |
| 같은 문단의 두 억원 금액이면 수치 불일치 | 같은 의미의 발행규모만 근거 값과 대조 | 서로 다른 금액의 정상 문장이 오탐됨 |
| 99% 자동화·1% 예외 | 전체 처리시간·누락·검토시간 측정 설계 | 실측 근거 없음 |
| 토큰 설계에 24시간 거래·원자적 결제 true | 구현 여부 false, 장래 시나리오 별도 | 설계안과 실제 운영 능력은 구분해야 함 |
| 교보를 발행인계좌관리기관으로 고정 | 기관 역할·인가·등록 경로 별도 확인 | 일반 계좌관리와 발행인계좌관리 제도 혼동 방지 |
| 수탁·복구 도입을 사실로 단정 | 미확인으로 처리 | 근거 원문·계약·운영 확인 없음 |
| 정책이 이미 전면 시행된 것처럼 서술 | 시행 전·초기·후속 확대·지연 시나리오 | 정책 준비와 실제 사업 범위 구분 |

같은 내용의 `_1` 파일과 원본 업로드 스크립트는 포함하지 않았다. 저장소 연결로 정상 커밋을 만들며 강제 push나 소스코드에 토큰을 넣는 방식은 사용하지 않는다.

지원서에서 주장할 수 있는 것은 공개 근거 정리, 시나리오별 교보의 선택·수익·위험 판단, 합성 입력의 점검 코드와 검증이다. 학교 수업에서 이미 수행했거나 회사에서 운영 성과를 냈던 경험으로 표현하지 않는다.
# 2026 반기 공시를 반영한 추가 판단

기존 프로젝트의 기관 MMF·사채 우선 가설을 현재 수익 기준선으로 보완했다. 주식·해외선물 중개와 조달·운용 마진의 방어, 반복 사모사채·기관 MMF 신규 수요 비교를 분리했다. 공개 공시 숫자는 `data/public/`에서 분석하고 합성 자산·문서 POC와 혼합하지 않는다. 세부 근거와 검증은 `KYOBO_BUSINESS_BASELINE.md`, `KYOBO_PROFIT_STRATEGY.md`, `VERIFICATION.md`에 있다.
